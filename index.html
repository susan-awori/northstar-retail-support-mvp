Go-Live Architecture Note: Prototype vs. Phase 2 Real Data Integration

Technical roadmap for Northstar Retail Co. engineering team

1. What Works End-to-End in this MVP (Sprint Deliverables)

  • Structured Data Lookups: Format validation (`#NS-XXXXXX`), order status tracking, and 30-day return eligibility processing.
  • Policy RAG Engine (`rag.js`): Split markdown policy chunks, TF-IDF keyword relevance scoring, and threshold fallback.
  • Deflection Metrics Counter: Live calculation of tickets deflected vs. escalated, saved via `localStorage`.
  • Simulated Customer Login: Session switcher for personalized customer context pre-filling.
  • Conscience Compass Honesty: Explicit mock disclosures for stock checks ("Notify Me" soft deflections).

2. What is Simulated / Mocked for Demo Purposes

  • Mock Data (`mockData.json`): Orders, inventory, and returns are static local JSON objects.
  • Simulated Auth: Customer dropdown operates purely on in-memory JS variables without passwords or tokens.
  • In-Browser RAG: Keyword matching runs locally in JS rather than calling a remote vector database API.

3. Phase 2 Production Requirements (Go-Live Specification)

🔒 Backend API & DB Decoupling:

Never connect the frontend widget directly to database credentials. All lookups must route through Northstar's authenticated API endpoints (`GET /api/v1/orders/:id`) protected by OAuth2/JWT tokens.

🔑 Production Auth Integration:

Replace the simulated customer dropdown with Northstar's existing identity provider. The widget receives an encrypted session token after verified login.

🧠 Automated Vector Store RAG Sync:

Replace static `policies/*.md` keyword search with automated embeddings (e.g. OpenAI `text-embedding-3-small` / Claude API) stored in a vector database (Pinecone or PGVector) that re-indexes automatically on CMS updates.

🇰🇪 Data Protection Compliance (Kenya Data Protection Act 2022):

All customer PII (order history, masked addresses) must follow strict data minimisation rules, audit logging, and encryption in transit/at rest before go-live.

📊 Server-Side Analytics Logging:

Move deflection metrics from `localStorage` to server-side telemetry so deflection rate calculations are accurate across millions of global web sessions.
